SPECIFICATION: Conduit (RealWorld) Blogging Platform API
============================================================

This application provides a REST API for a blogging platform.
The API is served under /api/. Authentication uses JWT tokens
passed via the Authorization header ('Token <jwt>').

## Article Management

- Create a user (username: 'author1', email: 'author1@test.com', password: 'pass123') and authenticate. Create an article with title 'My Test Article', description 'Test description', body 'Article body content', tagList ['testing', 'nestjs']. Verify response status is 201. Verify the returned article has 'title' equal to 'My Test Article', 'description' equal to 'Test description', 'tagList' containing 'testing' and 'nestjs', and 'slug' starting with 'my-test-article-' (lowercase with hyphen suffix). Extract the slug. Retrieve the article via GET /api/articles/{slug}. Verify status 200 and the returned article title is 'My Test Article'.

- Create a user (username: 'updateuser1', email: 'updateuser1@test.com', password: 'pass123'). Create an article with title 'Original Title', description 'Original description', body 'Original body'. Extract the slug. Update the article via PUT /api/articles/{slug} with new title 'Updated Title' and description 'Updated description'. Verify response status is 200. Verify the response article has 'title' equal to 'Updated Title' and 'description' equal to 'Updated description'. Verify the slug in the response is unchanged. Retrieve the article by the original slug. Verify the article has the updated values.

- Create a user (username: 'deleteuser1', email: 'deleteuser1@test.com', password: 'pass123'). Create an article with title 'Article To Delete'. Extract the slug. Verify the article can be retrieved via GET /api/articles/{slug}. Delete the article via DELETE /api/articles/{slug}. Verify response status is 200. Attempt to GET the article by slug again. Verify the response status is 200 with an empty object {} (implementation returns empty object for deleted articles rather than 404).

- Create user1 (username: 'feeduser1', email: 'feeduser1@test.com', password: 'pass123'), user2 (username: 'feedauthor1', email: 'feedauthor1@test.com', password: 'pass123'), and user3 (username: 'feedauthor2', email: 'feedauthor2@test.com', password: 'pass123'). User2 creates article 'Article By Followed'. User3 creates article 'Article By Not Followed'. Using user1's token, GET /api/articles/feed. Verify articlesCount is 0 (no follows yet). User1 follows user2. GET /api/articles/feed again. Verify articlesCount is 1. Verify the articles array contains 'Article By Followed' and does NOT contain 'Article By Not Followed'.

- Create a user (username: 'commentuser1', email: 'commentuser1@test.com', password: 'pass123'). Create an article with title 'Comment Test Article'. Extract the slug. Create a comment on the article via POST /api/articles/{slug}/comments with body 'This is my test comment'. Verify response status is 200. Verify the response article has comments array with length >= 1. GET the comments for the article via GET /api/articles/{slug}/comments. Verify status 200. Verify the comments array contains a comment with body 'This is my test comment'. Verify the comment has an 'id' field that is a number.

- Create a user (username: 'delcommentuser1', email: 'delcommentuser1@test.com', password: 'pass123'). Create an article with title 'Delete Comment Test'. Extract the slug. Create a comment with body 'Comment to delete'. Extract the comment id from the response. Verify the article has 1 comment. Delete the comment via DELETE /api/articles/{slug}/comments/{id}. Verify response status is 200. GET the article's comments. Verify the comments array is empty or does not contain the deleted comment body.

- Create a user. Create article1 with title 'First Tagged Article' and tagList ['javascript', 'testing']. Create article2 with title 'Second Tagged Article' and tagList ['python', 'testing']. Create article3 with title 'No Match Article' and tagList ['ruby']. GET /api/articles?tag=javascript. Verify articlesCount is 1 and articles array contains only 'First Tagged Article'. GET /api/articles?tag=testing. Verify articlesCount is 2 and articles array contains both 'First Tagged Article' and 'Second Tagged Article'. GET /api/articles?tag=nonexistent. Verify articlesCount is 0.

- Create user1 (username: 'articleauthor1', email: 'articleauthor1@test.com', password: 'pass123') and user2 (username: 'articleauthor2', email: 'articleauthor2@test.com', password: 'pass123'). User1 creates article 'User1 Article'. User2 creates article 'User2 Article'. GET /api/articles?author=articleauthor1. Verify articlesCount is 1 and contains only 'User1 Article'. GET /api/articles?author=articleauthor2. Verify articlesCount is 1 and contains only 'User2 Article'. This tests the author-article relationship established during article creation.

- Create a user (username: 'taglistuser1', email: 'taglistuser1@test.com', password: 'pass123'). Create an article with title 'Multi Tag Article' and tagList ['tag1', 'tag2', 'tag3']. Extract the slug from response. GET /api/articles/{slug}. Verify the article's tagList contains exactly ['tag1', 'tag2', 'tag3'] in array format. Create another article with empty tagList []. GET that article. Verify tagList is an empty array []. This tests the simple-array column handling for tagList.

- Create a user (username: 'timestampuser1', email: 'timestampuser1@test.com', password: 'pass123'). Create an article with title 'Timestamp Test Article'. Extract slug, created, and updated timestamps from response. Wait briefly, then PUT /api/articles/{slug} with updated title 'Updated Timestamp Article'. GET /api/articles/{slug}. Verify the 'created' timestamp is unchanged from original. Verify the 'updated' timestamp is different (newer) than the original. This tests the @BeforeUpdate hook that updates the timestamp.

- Create user1 (username: 'sluguser1', email: 'sluguser1@test.com', password: 'pass123'). User1 creates two articles with the SAME title 'Duplicate Title Article'. Verify both articles are created successfully (both return 201). Extract both slugs. Verify the two slugs are DIFFERENT from each other (random suffix makes them unique). Both slugs should start with 'duplicate-title-article-' but have different suffixes. This tests the slugify function that appends random suffix.

- Create user1 (username: 'fieldsuser1', email: 'fieldsuser1@test.com', password: 'pass123'). User1 creates an article with title 'Test Article Title', description 'Test article description content'. Extract the slug. GET /api/articles/{slug}. Verify the article's title is exactly 'Test Article Title' and description is exactly 'Test article description content'. This tests title and description field persistence.

- Create user1 (username: 'feedpageuser1', email: 'feedpageuser1@test.com', password: 'pass123'). Create user2 (username: 'feedpageauthor1', email: 'feedpageauthor1@test.com', password: 'pass123'). User1 follows user2. User2 creates 5 articles: 'Article 1', 'Article 2', 'Article 3', 'Article 4', 'Article 5'. User1 GETs /api/articles/feed?limit=2. Verify articlesCount is 5 (total) but only 2 articles returned. User1 GETs /api/articles/feed?limit=2&offset=2. Verify 2 different articles returned. This tests feed pagination.

- Create user1 (username: 'emptyfeeduser1', email: 'emptyfeeduser1@test.com', password: 'pass123'). Create user2 (username: 'emptyfeedauthor1', email: 'emptyfeedauthor1@test.com', password: 'pass123'). User2 creates an article 'Article by User2'. User1 (who follows nobody) GETs /api/articles/feed. Verify articlesCount is 0 and articles array is empty. This tests the empty follows check that returns empty result when user has no follows.

## User & Authentication

- Create a new user using the user creation endpoint with payload {user: {username: 'testuser123', email: 'test@example.com', password: 'password123'}}. Verify the response status is 201. Parse the response JSON and verify that the returned user object contains 'username' equal to 'testuser123', 'email' equal to 'test@example.com', and 'token' field is not empty. Extract the token from the response. Use the token to retrieve the current user information via the GET /api/user endpoint with Authorization header 'Token {token}'. Verify the retrieval response status is 200. Verify the retrieved user's 'username' is 'testuser123' and 'email' is 'test@example.com'.

- Create a user (username: 'uniqueuser1', email: 'unique1@test.com', password: 'pass123'). Verify status 201. Attempt to create another user with the same username but different email (username: 'uniqueuser1', email: 'different@test.com'). Verify the response status is 400. Verify the response contains 'Username and email must be unique'. Attempt to create another user with different username but same email (username: 'differentuser', email: 'unique1@test.com'). Verify the response status is 400. Verify the response contains 'Username and email must be unique'.

- Create a user with username 'logintest1', email 'logintest1@test.com', password 'correctpass123'. Then POST /users/login with email 'logintest1@test.com' and password 'correctpass123'. Verify response status is 201 and response contains 'user' object with matching email and username, and a valid token. Then POST /users/login with same email but WRONG password 'wrongpass456'. Verify response is 401 (unauthorized). This tests the argon2 password verification logic.

- Create a user with username 'updateuser1', email 'updateuser1@test.com', password 'pass123'. Extract the token. PUT /api/user with body {"user": {"bio": "Updated bio text", "image": "https://example.com/newimage.jpg"}}. Verify response status is 200. Verify response contains updated bio 'Updated bio text' and image 'https://example.com/newimage.jpg'. GET /api/user with the token. Verify the updated bio and image persisted.

- Create user1 (username: 'jwtuser1', email: 'jwtuser1@test.com', password: 'pass123'). Extract the JWT token from the response. Decode the JWT token payload (base64 decode the middle segment). Verify the payload contains: id matching the user's id, username equal to 'jwtuser1', email equal to 'jwtuser1@test.com'. Use the token to GET /api/user and verify the returned user matches. This tests the JWT payload generation in generateJWT method.

- Create user1 (username: 'orphanauthor1', email: 'orphanauthor1@test.com', password: 'pass123'). User1 creates article with title 'Orphan Article Test'. GET /api/articles and verify article exists with author username 'orphanauthor1'. DELETE /api/users/orphanauthor1@test.com. Verify response is 500 (FK constraint error). GET /api/articles again and verify article still exists. This tests that articles block user deletion (no CASCADE DELETE configured).

## Profiles & Following

- Create user1 (username: 'profileviewer1', email: 'profileviewer1@test.com', password: 'pass123') and user2 (username: 'profiletarget1', email: 'profiletarget1@test.com', password: 'pass123'). Using user1's token, GET /api/profiles/profiletarget1. Verify profile has 'following' equal to false (no relationship yet). User1 follows user2 via POST /api/profiles/profiletarget1/follow. GET /api/profiles/profiletarget1 again with user1's token. Verify profile has 'following' equal to true and username is 'profiletarget1'. User1 unfollows user2. GET /api/profiles/profiletarget1 again. Verify profile has 'following' equal to false again. This tests the follow status lookup in findProfile method.

- Create user1 (username: 'profilebiouser1', email: 'profilebiouser1@test.com', password: 'pass123'). Update user1's profile with bio 'This is my bio text' and image 'https://example.com/avatar.jpg' via PUT /api/user. GET /api/profiles/profilebiouser1. Verify the profile contains username 'profilebiouser1', bio 'This is my bio text', and image 'https://example.com/avatar.jpg'. This tests profile data retrieval.
