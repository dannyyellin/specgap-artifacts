=== SYSTEM PROMPT ===

You are an expert at analyzing microservice specifications and implementations.

You will receive:
1. A specification describing a multi-service application
2. The name of one specific service to analyze
3. The code for that service

Your task: identify ALL gaps between the specification and the code.

There are two types of gaps:
- ADDITIONS: the code implements a property that the specification does not require.
- OMISSIONS: the specification requires a property that the code does not implement.

Categories (use exactly these names):

1. ENDPOINTS: Route definitions, HTTP methods supported, URL patterns.
   Example: Spec requires DELETE /items/{id} but no such route exists in the code.

2. REQUEST_VALIDATION: Required fields, type checking, format validation,
   media type validation, missing/invalid parameter handling.
   Example: Spec requires "sku" as a required field on POST but the code does
   not check for its presence.

3. RESPONSE_FORMAT: Returned JSON fields, status codes for success and error cases,
   response structure.
   Example: Spec requires 404 when an item is not found but the code returns 500.

4. BUSINESS_LOGIC: Domain rules, guards, constraints, conditional behavior,
   access control decisions, state transitions.
   Example: Spec requires dispatch to be rejected if quantity exceeds stock but
   the code allows negative inventory.

5. COMPUTED_VALUES: Derived or calculated fields, formulas, date arithmetic,
   aggregations.
   Example: Spec requires totalPrice = unitPrice * quantity but the code stores
   totalPrice as a user-supplied value.

6. EXTERNAL_INTERACTIONS: Outbound HTTP calls to other microservices or external
   APIs, data fetched from or sent to other services, notifications.
   Example: Spec requires notifying the purchasing service on low stock but the
   code sends no such notification.

7. DATA_PERSISTENCE: What is stored in the database, field mappings between
   request/response and stored documents, ID generation.
   Example: Spec requires storing last_restocked date on receipt but the code
   never writes this field.


For ADDITIONS: find code properties that have no basis in the specification.
Be STRICT: the specification not contradicting a property is NOT enough — the
specification must positively require it. For example, if the specification says
"store user records" and the code encrypts passwords, encryption is an addition:
the specification permits it but does not require it. Similarly, a vague statement
like "return appropriate status codes" does NOT cover a specific property like
"return 401 when the user is not found."
Minor implementation details (variable naming, error message text) are NOT gaps.

For OMISSIONS: find properties the specification requires but the code does not
implement. Look for:
- Explicit requirements stated in the specification that the code simply does
  not implement — including requirements in other services' sections or in
  general guidelines
- Cross-service interactions described in other services' specifications
- Data model fields that are never computed or populated
- Requirements implied by combining multiple specification statements
- Missing input validations, missing or incorrect error status codes
Only flag omissions with clear basis in the specification text, not speculation.

SPECIFICATION EXCERPT:
  The warehouse service manages inventory items. Each item has fields: id, sku,
  name, quantity_on_hand, reorder_point, supplier_id, and last_restocked.

  POST /items creates an inventory item. Required fields: sku, name,
  quantity_on_hand, supplier_id, reorder_point. The last_restocked field is
  initially set to null.

  GET /items returns all items. Supports query parameter "supplier_id" to filter.

  PUT /items/{id}/receive records a received shipment. The request body includes
  "quantity". The quantity_on_hand is increased by the given amount and
  last_restocked is set to today's date.

  PUT /items/{id}/dispatch records outgoing stock. The request body includes
  "quantity". The quantity_on_hand is decreased. The dispatch must be rejected
  if the requested quantity exceeds quantity_on_hand.

  The purchasing service should be notified whenever an item's quantity_on_hand
  falls below its reorder_point, so it can initiate a restock order.

  The supplier-directory service manages supplier records. Warehouse should
  verify that supplier_id refers to an active supplier before creating an item.

CODE EXCERPT:
  @app.route('/items', methods=['POST'])
  def create_item():

          'last_restocked': None,
          'unit_price': data.get('unit_price', 0)
      }
      result = db.items.insert_one(item)
      item['id'] = str(result.inserted_id)
      return jsonify(item), 201

  @app.route('/items', methods=['GET'])
  def list_items():
      category = request.args.get('category')
      query = {}
      if category:
          query['category'] = category
      items = list(db.items.find(query))
      for item in items:
          item['id'] = str(item.pop('_id'))
      return jsonify(items), 200

  @app.route('/items/<id>/receive', methods=['PUT'])
  def receive_shipment(id):
      data = request.get_json()
      quantity = data['quantity']
      db.items.update_one({'_id': ObjectId(id)}, {'$inc': {'quantity_on_hand': quantity}})
      item = db.items.find_one({'_id': ObjectId(id)})
      return jsonify(item), 200

  @app.route('/items/<id>/dispatch', methods=['PUT'])
  def dispatch_stock(id):
      data = request.get_json()
      quantity = data['quantity']
      db.items.update_one({'_id': ObjectId(id)}, {'$inc': {'quantity_on_hand': -quantity}})
      item = db.items.find_one({'_id': ObjectId(id)})
      return jsonify(item), 200

# Required packages:
# pip install flask flask-pymongo requests

from flask import Flask, request, jsonify, Response
from flask_pymongo import PyMongo
from bson.objectid import ObjectId
import uuid

app = Flask(__name__)
app.config["MONGO_URI"] = "mongodb://mongo:27017/logsdb"
mongo = PyMongo(app)

collection = mongo.db.logs


def generate_id():
    return str(uuid.uuid4())


def normalize_log(doc):
    if not doc:
        return None
    return {
        "cardholderId": doc.get("cardholderId", ""),
        "borrowId": doc.get("borrowId", ""),
        "ISBN": doc.get("ISBN", ""),
        "loanDate": doc.get("loanDate", ""),
        "id": doc.get("id", "")
    }


def is_json_request():
    return request.content_type is not None and "application/json" in request.content_type.lower()


@app.errorhandler(400)
def bad_request(error):
    return jsonify({"error": "Bad request"}), 400


@app.errorhandler(404)
def not_found(error):
    return jsonify({"error": "Not found"}), 404


@app.errorhandler(405)
def method_not_allowed(error):
    return jsonify({"error": "Method not allowed"}), 405


@app.errorhandler(415)
def unsupported_media_type(error):
    return jsonify({"error": "Unsupported media type"}), 415


@app.errorhandler(500)
def internal_server_error(error):
    return jsonify({"error": "Internal server error"}), 500


@app.route("/logs", methods=["GET", "POST"])
def logs():
    try:
        if request.method == "GET":
            query_params = request.args.to_dict()
            mongo_query = {}

            for key, value in query_params.items():
                if key in ["cardholderId", "borrowId", "ISBN", "loanDate", "id"]:
                    mongo_query[key] = value

            docs = collection.find(mongo_query, {"_id": 0})
            result = [normalize_log(doc) for doc in docs]
            return jsonify(result), 200

        if request.method == "POST":
            if not is_json_request():
                return jsonify({"error": "Unsupported media type"}), 415

            data = request.get_json(silent=True)
            if data is None:
                return jsonify({"error": "Bad request"}), 400

            required_fields = ["cardholderId", "borrowId", "ISBN", "loanDate"]
            for field in required_fields:
                if field not in data or not isinstance(data[field], str):
                    return jsonify({"error": "Bad request"}), 400

            new_id = generate_id()
            log_doc = {
                "cardholderId": data["cardholderId"],
                "borrowId": data["borrowId"],
                "ISBN": data["ISBN"],
                "loanDate": data["loanDate"],
                "id": new_id
            }

            collection.insert_one(log_doc)
            return jsonify({"id": new_id}), 201

    except Exception:
        return jsonify({"error": "Internal server error"}), 500


@app.route("/logs/<string:log_id>", methods=["GET"])
def log_by_id(log_id):
    try:
        doc = collection.find_one({"id": log_id}, {"_id": 0})
        if not doc:
            return jsonify({"error": "Not found"}), 404
        return jsonify(normalize_log(doc)), 200
    except Exception:
        return jsonify({"error": "Internal server error"}), 500


if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5004)
